# Required Lesson Guide Fields

[[Course/Runtime Teaching Contract]]

Use these fields when preparing a lesson guide. Preparation is not evidence of understanding; the tutor fills learner-specific runtime fields from actual attempts.

- **Identity, goal and scope:** exact lesson key, title, source IDs or variants, unit, bounded class objective and guardrails. Resolve ambiguous numbers by title. No unrelated advanced prerequisites.
- **Targets and foundations:** concrete core knowledge, learning targets, relevant prerequisite strands and definitions/theorem hypotheses. Audit proposed roots rather than calling a theorem unconditional.
- **Source provenance:** original class asset paths, source URLs/retrieval dates, availability and inspected-page evidence; distinctly labeled original supplemental questions, textbook exercise locators, MIT/Paul perspectives and released exam routes. Cached is not inspected; a locator is not a verified solution.
- **Depth plan:** motivation, justified reasoning path, worked-example route, explicit dependency connections, contrast/failure case and independent transfer. Use inspected course notation and reasoning demands. Unpublished class notes remain unavailable; proposed adaptations stay labeled.
- **Diagnostic blueprint:** a sound floor, sharper in-scope escalation and surrounding probe after a miss for every consequential strand. Record a demonstrated scope boundary when appropriate. Difficulty labels are relative to this strand, not exam predictions.
- **Assessment blueprint:** compact direct check and a distinct fresh question with a different representation; identify the requested reasoning and verify solutions before use. Separate instructor keys from unanswered learner prompts. A saved application question does not automatically qualify as transfer.
- **Evidence and errors:** actual submitted quiz IDs, learner reasoning, honest reviews, separate concept/algebra/notation/graph/context observations, and direct-plus-transfer verification status. Use unclassified if ambiguous, especially after dictation.
- **Resume and review:** learner-approved DAG, current node, exact unfinished question, inspected sources, observed weaknesses and next review date. Do not overwrite the student checkpoint during curriculum generation.
- **Assessment timing:** published coverage and original tentative dates with conflicts/unknowns preserved. Test preparation uses saved weaknesses. Never invent future assessment questions, weights, unpublished lesson content or deadlines.

Use these fields across subjects; depth means connected reasoning and actual attempts across turns, not a unit-length monologue or a fixed quota. Preserve personal notes, checkpoints and lock state when revising a guide.
